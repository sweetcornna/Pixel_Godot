# CI 闸门实测记录

一个**永远通过的 CI 没有价值**。这份文档是 `.github/workflows/ci.yml` 的判据：
它记录 CI 对哪些破坏真的红过，以及首跑抓到了什么。

与 `tools/godot-gate/README.md`、PLAN §8.1 的无缝判据是同一条纪律 ——
只看绿灯等于没验。

---

## 首跑：三平台矩阵（2026-08-03）

本项目至今只在 Linux 上开发。CI 是**第一次**在 Windows 与 macOS 上执行全套件。

| 平台 | 结果 |
|---|---|
| ubuntu-latest · py3.12 | ✅ |
| ubuntu-latest · py3.14 | ✅ |
| macos-latest · py3.12 | ✅ 首跑即过 |
| windows-latest · py3.12 | ❌ **抓到一个真实的可移植性 bug** |

### Windows 抓到了什么

```
AssertionError: assert 'frames\\static.png' == 'frames/static.png'
```

22 处 `str(path.relative_to(root))` 在 Windows 上产出平台原生分隔符，直接写进
Manifest。**这不是测试的毛病，是产品 bug**：Manifest 是跨平台契约
（ADR-001：凭它加上文件就能重建全部产物），而**反斜杠在 Linux 上是合法文件名
字符** —— Windows 上产出的 Manifest 拿到 Linux 会报"文件不存在"，
一个毫无线索的错误形态。

修在 `AssetRelativePath` 的验证器里，不是 22 个调用点：那 22 处漏一处就前功尽弃，
而验证器是所有路径进 Manifest 的**唯一收口**。

同时补了 7 条**在 Linux 上就能抓住它**的单测。不写它，这个 bug 就只有 Windows CI
看得见，而 Windows CI 是几个月才有人看一眼。其中一条专门验归一化没有打开逃逸
口子：反斜杠版的 `..\..\pwned.png` 仍须被拒。

> 契约里写死了「红了如实记账，**不许为了绿灯把平台从矩阵里删掉**」——
> 删掉等于把"我们不支持 Windows"伪装成"我们支持且通过"。这次没删，修了。

## 三类破坏各推一次（2026-08-03）

每类在 `pixel_asset_forge/planning/wfc.py` 上故意改坏一处，开 draft PR 触发 CI，
看完即关、分支即删。

| 故意改坏 | `ruff + mypy` | `pytest` × 4 平台 | 判读 |
|---|---|---|---|
| 未使用的 `import os`（F401） | **❌ 红** | 全绿 | 只红 lint —— 精确定位 |
| `MAX_RESTARTS: int = "8"` | **❌ 红** | **全红** | 类型错同时是运行时错，两处都该红 |
| `MAX_RESTARTS = 0`（改坏行为） | 全绿 | **全红** | lint 干净、行为红 —— 精确定位 |

第一行与第三行尤其重要：**它们各自只红该红的那一步**，不是"一坏全坏"。
这排除了"CI 随便什么改动都红"这种假阳性 —— 一个见谁都咬的门槛与一个谁都不咬的
门槛同样没用。

## 一条比 CI 本身更值钱的教训：反例本身也需要被验证

第一次做 lint 自检时，CI **判通过了**。查下来不是 CI 漏了，是**我的反例无效**：

```bash
sed -i '1a import os' pixel_asset_forge/planning/wfc.py
```

该文件第 1 行是模块 docstring 的 `"""`，插进去的 `import os` 落在**docstring
内部** —— 那是一段文本，不是代码。ruff 判通过完全正确。

重做时先在本地跑 `ruff check`，看到 `Found 2 errors` 才推。

这不是孤例。同一轮开发里同类错误出现过四次：

| 场次 | 无效反例 | 为什么无效 |
|---|---|---|
| §8.2 | 用纯色块验"tile 被改过" | 纯色块依旧只跟自己相容，邻接表一字未变 |
| §8.4 | off-by-one 的行过滤 | 所有行都被滤掉，断言退化成 `[] != []` |
| Godot 门槛 | 3 块 tile 的坐标转置 | 坐标集转置后等于自己，文件逐行等价 |
| §9.1 | `sed '1a'` 插 import | 插进了 docstring 内部 |

共同点：**构造完反例就直接用，没有先验证"它确实破坏了"**。

> **规矩：任何用来验证防线的反例，推之前必须先确认它真的坏了。**
> 本地能跑的就本地跑一遍（`ruff` / `mypy` / `pytest`）；本地跑不了的，
> 至少要说清楚"它凭什么应该失败"，并检查那个理由在当前数据上成立。
>
> 无效的反例比缺反例更危险：缺反例只是没验，无效反例会让人**以为验过了**，
> 甚至误导人去补一个并不存在的洞（Godot 门槛那次就险些如此）。

### 补充：验证工具本身也要有基线

§9.2 做 Skill 防漂移闸门时，四条反例第一次跑**全报"没抓住"**。查下来不是闸门
漏了，是探针坏了：`pyproject` 已有 `addopts = "-q"`，探针里又加了一个 `-q`，
`-qq` 让 pytest 把汇总行也吞掉，于是 `grep "failed"` 永远匹配不到。

> **规矩：验证脚本必须先跑一次"不改动"的基线，确认它在正常情况下报通过。**
> 没有基线就分不清「反例没被抓住」与「验证脚本根本没跑起来」——
> 两者的输出长得一模一样，而结论完全相反。
>
> 判成功/失败优先用**退出码**，不要 grep 输出文本：输出格式会被
> `addopts`、终端宽度、语言环境改变，退出码不会。

同一轮里另一个教训：**闸门误报比闸门漏报更容易造成实际损害。** 那次闸门报
"`--one-shot` 这个选项不存在"，而它是真的（`--loop/--one-shot` 布尔对的反面，
click 存在 `secondary_opts` 里）。不查就照着改文档的话，会把一个正确的用法删掉 ——
人会照着红叉去改，所以红叉本身必须先被质疑一次。

## 怎么重跑

```bash
# 三平台矩阵：推一个 PR 即可，或
gh workflow run CI --ref <branch>

# 自检：故意改坏一处，先本地确认它真的坏了，再开 draft PR
ruff check pixel_asset_forge   # 或 mypy / pytest —— 必须先看到红
gh pr create --draft --title "【CI 自检 · 跑完即关】..."
```
