# ADR-004：自适应阈值色键为主路径，四级降级兜底

- **状态**：已接受
- **日期**：2026-07-29
- **修订**：2026-07-29 —— 按 [Sprint 0 验证报告](../sprint-0-report.md) A-5 的实测数据重写。
  六档阶梯缩为五档，`fallback_stage` 由位置整数改为具名枚举。
- **相关**：[ADR-002](ADR-002-provider-abstraction.md) · [PLAN §2.4](../PLAN.md)

---

## 背景

游戏资产必须是透明背景的 RGBA PNG。但：

> **`gpt-image-2` 不支持透明背景。** 传入 `background: "transparent"` 会直接返回错误。

因此必须先生成不透明图，再在本地移除背景。可选路径：

- **色键（chroma key）**：让模型画在纯色背景上，本地按颜色距离阈值抠掉。
- **语义抠图**：用 `rembg` 之类的模型推断前景。
- **换模型**：同代的 `gpt-image-1.5` **支持**透明背景。

### Sprint 0 推翻的前提：模型画不出精确的键控色

本 ADR 的初版把"默认键控色**精确**色键"定为第 1 档。实测数据直接否定了它：

| 指标 | 第一轮样本 | 第二轮样本 |
|---|---|---|
| 精确 `#FF00FF` 像素占比 | **0.00%** | ~0.2% |
| 背景实际均值 | `#F204EA` | `#F304EF` |
| 与 `#FF00FF` 的颜色距离 p50 | 24 | 19 |
| 背景区域的唯一颜色数 | 345 / 40,960 px | 348 / 42,576 px |

模型产出的是一片**恒定偏移约 20 个颜色距离、且带轻微噪声**的近洋红，
而不是一片精确的 `#FF00FF`。按精确匹配实现的第 1 档，命中率是零 ——
它一个像素都抠不掉，然后把 100% 的图交给下一档。这一档不是"很少触发"，
而是**永远不会成功**，留着只会浪费一次处理开销并误导排障。

好消息是同一批数据也证明了宽容阈值极其可靠：

```text
 20–30  1,033,997  ← 背景簇（65.7%）
 30–40     17,028
 40–60      4,059
 60–80      1,650   ← 40–200 区间合计仅占 0.76%
 80–100     1,274
100–130     1,715
130–160     1,330
160–200     1,976
200–260     51,167  ← 前景簇
260–340    304,663
```

背景簇与前景簇之间是一条**极宽的空谷**。Otsu 自动阈值稳稳落在谷中，
产出的掩膜 8 个轮廓完整分离、无孔洞、无噪点、角色内部零误伤。

## 决策

**以「自适应阈值色键 + Despill」为主路径，并定义五档降级阶梯。**

| 档位 | 标识 | 含义 | 何时触发 |
|:---:|---|---|---|
| 1 | `tolerant_key` | 默认键控色 + **逐图自适应阈值** + Despill | 主路径 |
| 2 | `alt_key_color` | 切换备用键控色（`#00FF00` → `#00FFFF`），仍用自适应阈值 | 生成**前**冲突预检命中 |
| 3 | `transparent_model` | 改用 `gpt-image-1.5` 重生成，直接请求 `background: transparent` | 键控结果不合格 |
| 4 | `rembg` | 语义抠图 | 上一档仍不合格 |
| 5 | `manual` | 人工审核 | 兜底 |

第 1、2 档在**生成前**就已确定（取决于冲突预检）；第 3~5 档是**生成后**的逐级升级。

处理链：

```text
纯色背景 → 自适应阈值求解 → 颜色距离阈值检测 → 与画布外缘连通性过滤
→ Alpha 透明化 → Despill 去除彩边 → 清零透明像素的 RGB → 保存 RGBA PNG
```

### 决策要点一：阈值必须逐图求解，不能写死常数

两轮样本的背景距离 p50 分别是 24 和 19 —— 同一个 prompt 模板、同一个模型，
背景色就已经在漂。写死任何常数都会在某一批图上失效。

做法：对「每个像素到键控色的颜色距离」直方图做 Otsu 二分。
这在本项目里格外可靠，因为色键场景天然是双峰分布 —— 背景一簇、前景一簇，
中间的空谷宽达 160 个距离单位。

**阈值求解结果必须写入 Manifest**，与键控色同等对待：否则 `process` 重跑时
重新求解一遍，可能得到不同阈值，离线复现就不成立了。

### 决策要点二：连通性过滤是掩膜的必要组成

只按颜色距离判定会把**角色内部**恰好接近键控色的像素也判为背景，抠出洞来。
因此阈值判定之后必须再做一步：**只保留与画布外缘连通的背景区域**。

实现上有个具体的坑，值得写进 ADR：`scipy.ndimage` 的形态学运算在图像边界
按"外部为前景"处理，会把最外一圈背景直接吞掉，导致从边缘泛洪的种子成为空集、
掩膜全黑。**必须先补一圈再做形态学**（或显式传 `border_value=1`）。
这个错误在 Sprint 0 调试中真实发生过，且症状具有欺骗性 ——
掩膜全黑表现为"前景占比 100%"，看起来像阈值选错了。

### 决策要点三：键控色不能硬编码

固定 `#FF00FF` 会在遇到**粉/紫/洋红系角色**时把角色本体一起抠掉 —— 史莱姆、法师袍、
魔法特效、粉色头发都会触发。这不是边缘情况：三套测试角色中的 Slime 就是专门用来暴露这个问题的。

因此：

1. 生成**前**从角色描述与目标调色板做冲突预检。
2. 冲突时按序切换：`#FF00FF` → `#00FF00` → `#00FFFF`。
3. 三者都冲突时报错并要求用户显式指定。
4. **将实际使用的键控色写入 Manifest 的 `background.color_used`**。

第 4 点是关键：处理与验证阶段必须能脱离原始请求独立复现，而这只有在实际使用值被持久化后才成立。
Manifest 同时记录 `color_requested` 与 `color_used`，两者不同即说明触发了冲突降级。

> 词表匹配必须按**词边界**，不能用子串。`slime` 里含 `lime`，
> 子串匹配会把史莱姆判为与纯绿冲突 —— 而它本该降级到的正是纯绿。
> CJK 没有词边界概念，只能用子串，这是可接受的不对称。

### 决策要点四：`transparent_model` 优先于 `rembg`

同代的 `gpt-image-1.5` 支持 `background: transparent`，产出的是**原生 alpha 通道**。
这在质量上显著优于 `rembg` 的语义抠图 —— 后者在像素画的硬边缘与细小肢体（手指、剑尖、飘带）
上表现很差，会产生半透明羽化边和肢体缺失，而这恰恰是像素资产最不能容忍的。

因此降级顺序是：**换模型 > 语义抠图**，而非直接跳到 `rembg`。

### 决策要点五：档位用具名标识，不用序号

初版用 `fallback_stage: 1..6` 这样的位置整数。本次修订删掉一档，
所有序号的含义都要平移 —— 任何已落盘的 Manifest 都会被静默误读，
日志里的"第 4 档"也会从"换模型"变成"rembg"。

具名标识（`tolerant_key` / `alt_key_color` / …）对增删档位免疫，
且在日志与验证报告里自解释。代价是 Manifest schema 的一次 MAJOR 升级
（[PLAN §5.4](../PLAN.md)），换来的是此后增删档位不再需要升级。

## 理由

### 为什么色键仍是主路径

色键是**纯像素运算，100% 确定性**：

- 可被 golden image 测试完全覆盖
- 失败模式单一且可解释（背景色与前景色距离过近）
- 无外部模型依赖，无推理开销
- 在像素画的硬边缘上表现最好 —— 没有羽化，边界就是边界

自适应阈值不破坏确定性：Otsu 是对给定图像的纯函数，同一张输入必得同一个阈值。

`rembg` 则引入了 ONNX 运行时依赖、数百 MB 模型文件、不可复现的推理结果，
以及针对照片训练、对像素画适配不佳的固有问题。

### 为什么 despill 是必需的

即使背景被正确抠掉，紧邻背景的前景像素也会带上键控色的溢色（洋红边）。
Sprint 0 实测：落在 40–200 距离区间的光晕像素约占全图 **0.76%** ——
绝对量不大，但它们全部集中在角色轮廓线上。

像素画的调色板通常只有 16–24 色，一圈洋红边会直接污染调色板量化结果，
表现为"莫名其妙多出几个紫色"。despill 必须在量化之前执行。

### 为什么要清零透明像素的 RGB

`alpha=0` 的像素其 RGB 值在多数渲染器中不可见，但会：

- 影响 PNG 压缩率
- 在某些引擎的 mipmap / 双线性过滤下渗出色边
- 干扰调色板统计

因此强制清零，并作为一个**致命级验证项**（[PLAN §9.2](../PLAN.md)）。

## 后果

**正面**

- 主路径完全确定性、可测试、无外部依赖，且已有实测数据支撑（Sprint 0 / A-5）。
- 删掉一个必然失败的档位，排障时少一层噪声。
- 具名档位使后续增删阶梯不再触发 schema 升级。
- 降级阶梯覆盖了从"颜色冲突"到"模型就是画不好"的全部失败模式。
- `rembg` 保持为**可选依赖**，不装也能用全部核心功能。
- 键控色与阈值写入 Manifest，使 `pixel-asset process` 能离线精确重跑。

**负面**

- 自适应阈值引入了一个"求解可能失败"的新失败模式：若某张图不是双峰分布
  （例如背景被大面积遮挡），Otsu 会给出无意义的阈值。缓解：求解后校验
  背景占比是否落在合理区间（经验值 30%–95%），越界则告警并升到下一档。
- 需要维护双模型路径（`transparent_model` 档），`gpt-image-1.5` 与 `gpt-image-2`
  的生成质量有差异，产出风格可能不完全一致。因此该档定位为**兜底而非主路径**，
  且触发时应在验证报告中告警。
- 背景色冲突预检本身可能误判（描述里提到"紫色"但实际只是一个小配饰）。
  缓解：预检偏保守（宁可换色），换色的代价接近于零。
- 五档阶梯仍有实现与测试复杂度。缓解：`rembg` 与 `manual` 两档在 MVP 中可以只留接口不实现。

## 备选方案

**A. 保留「精确色键」作为快速路径**
被否决。实测命中率为零 —— 它不是"很少成功"，是"永远不成功"。
留着只会让每张图多跑一次注定失败的判定，并在排障时制造噪声。

**B. 用固定的宽容阈值（如距离 ≤ 60）**
被否决。两轮样本的背景距离 p50 就差了 24 vs 19，固定阈值必然在某批图上失效。
自适应求解的成本只是一次直方图统计，没有理由省。

**C. 直接用 rembg 作为主路径**
被否决。引入重量级依赖，结果不可复现，且在像素画硬边缘上质量差于色键。

**D. 全程使用 gpt-image-1.5（原生透明）**
被否决。`gpt-image-2` 在角色一致性与指令遵循上更强，而**身份一致性是本项目最难解决的问题**
（Sprint 0 / A-6 实测 16 个格子零漂移，证明这条路走得通）。
为了省掉抠图这个已经完全解决的问题，去牺牲最难的那个问题，不划算。

**E. 让模型画在白色背景上**
被否决。白色在角色高光、盔甲反光、眼白上大量出现，冲突率远高于洋红。
洋红/纯绿/纯青之所以是行业惯例，正是因为它们在自然图像中极少出现。

**F. 固定键控色不做冲突检测**
被否决。这正是 v1 稿的方案。三套测试角色中的 Slime 会立刻暴露该问题，属于必然踩到的坑。
