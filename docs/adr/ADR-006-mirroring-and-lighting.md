# ADR-006：左右镜像与固定光照的冲突取舍

- **状态**：已接受
- **日期**：2026-07-29
- **相关**：[ADR-003](ADR-003-fixed-grid.md) · [PLAN §9.4](../PLAN.md)

---

## 背景

系统中有两条规则互相冲突：

**规则 A**（Asset Request 的 style 段）：

```yaml
style:
  lighting: fixed_top_left    # 光源固定左上
```

**规则 B**（左右方向镜像 derive）：

> 只有满足以下条件时才镜像：没有固定手持武器、没有盾牌、没有单侧饰品、服装左右基本对称。
> ```json
> { "right": { "derived_from": "left", "transform": "flip_horizontal" } }
> ```

**冲突**：水平翻转会把左上方的光源翻到右上方。`walk_left` 的高光在角色左侧，
镜像得到的 `walk_right` 高光就在角色右侧 —— 两个方向的光照方向不一致。

这个矛盾必须在设计阶段解决。如果留给实现者临时判断，
结果是产出"通过了全部验证但看起来不对"的资产 —— 因为几何类验证项
（帧数、尺寸、锚点、轮廓）对光照方向完全不敏感。

## 决策

**接受该不一致，默认启用镜像。**

同时提供 `style.strict_lighting: true` 开关。开启后：

- 禁用一切镜像
- 四个方向全部独立生成

镜像的前置条件（全部满足才可镜像）：

- 没有固定手持武器
- 没有盾牌
- 没有单侧饰品
- 服装左右基本对称

Manifest 记法：

```json
{
  "walk_right": {
    "derived_from": "walk_left",
    "transform": "flip_horizontal"
  }
}
```

**验证要求**：derive 出来的方向**不参与身份漂移与轮廓类校验**（它在几何上必然与源方向一致，
校验没有信息量），但仍需通过尺寸、锚点、透明 RGB 等确定性检查。

## 理由

### 为什么接受不一致

**1. 镜像方向的身份一致性是 100% 的。**

这是最重要的理由。**镜像得到的方向与源方向在身份上绝对一致** ——
服装、武器、比例、配色完全相同，不存在任何漂移。而独立生成的 `right` 方向
必然引入身份漂移风险，**而身份漂移是本项目最难解决的问题**。

换句话说：镜像用一个几乎不可察觉的光照瑕疵，换掉了一个真实存在的严重风险。
少生成一个方向，就是少一次漂移的机会。

**2. 在目标分辨率下几乎不可察觉。**

目标逻辑尺寸是 16×16 到 96×96，主力档位是 32×32。在 32×32 的角色上，
两侧的明暗差异通常只体现在几个像素上。像素游戏的既有实践广泛使用镜像方向，
玩家对此并无感知 —— 这是行业惯例而非妥协。

### 为什么不选"镜像后重打高光"

技术上可行：翻转后识别高光区域并重新映射到另一侧。但：

- 需要可靠地识别"哪些像素是高光" —— 在 24 色调色板下，高光与固有色的浅色调难以区分
- 引入一个不确定的启发式步骤到本应完全确定性的处理链中（违反 [ADR-003](ADR-003-fixed-grid.md) 的精神）
- 修复错误的高光比原本的不一致更糟

若未来确有需求，可作为 P3 的可选后处理器，但不进入第一版。

### 为什么仍要提供 strict_lighting 开关

有两类场景确实需要严格光照：

- 高分辨率资产（96×96 及以上），光照不一致开始可见
- 侧视角（platformer）游戏，角色始终以侧面示人，左右方向的光照差异会被放大

给用户一个明确的开关，比替用户做死决定更好。默认值选择"启用镜像"是因为它匹配主流场景。

## 后果

**正面**

- 消除了规则冲突，实现者不需要临时判断。
- 默认路径下 `left` / `right` 两个方向的身份零漂移。
- 需要严格光照的用户有明确的退出路径。

**负面**

- `left` / `right` 方向的光照方向不一致。**这是一个已知且被接受的瑕疵**，必须在 README 中明示，避免用户误报为 bug。
- 镜像前置条件（无武器、无盾、无单侧饰品、服装对称）需要判断。第一版由用户在 request 中显式声明 `mirroring.enabled`，**不做自动推断** —— 自动推断一旦误判（把带剑角色镜像成左撇子），这个错误能通过全部自动验证项，只有人眼能发现。
- `strict_lighting: true` 时需要多生成一个方向，`pixel-asset plan` 的任务数应正确反映。

## 备选方案

**A. 禁用镜像，四方向全部独立生成**
被否决为默认值（保留为 `strict_lighting: true`）。多一个独立生成的方向，就多一次身份漂移的机会。

**B. 取消 `fixed_top_left`，改为"光源随朝向"**
被否决。会让 `down` / `up` 方向的光照也失去一致性，问题从"左右不一致"扩大为"四方向都不一致"，且失去了统一光照带来的整体协调感。

**C. 镜像后重打高光**
被否决。引入不确定的启发式步骤，且高光识别在低色数调色板下不可靠。可作为 P3 备选。

**D. 自动推断能否镜像（从描述中检测武器/盾牌关键词）**
被否决。误判代价高（带剑角色被镜像成左撇子，且这个错误能通过所有自动验证项），
而让用户填一个布尔字段几乎没有负担。第一版由用户显式声明。
