# ADR-002：Provider 解耦

- **状态**：已接受
- **日期**：2026-07-29
- **相关**：[ADR-001](ADR-001-manifest-first.md) · [ADR-004](ADR-004-chroma-key.md) · [PLAN §2.7](../PLAN.md)

---

## 背景

项目的核心生成能力依赖 `gpt-image-2`，但有四个因素要求生成层必须可替换：

1. **开发期需要完全离线的迭代循环。** 每次跑单元测试或调试处理逻辑都调用真实 API，延迟不可接受，而且每次拿到的图都不一样，无法判断改动是否有效。
2. **透明背景降级路径需要切换到 `gpt-image-1.5`**（见 [ADR-004](ADR-004-chroma-key.md)）。这意味着同一次资产生成过程中就可能涉及两个模型。
3. **API 会变。** 模型版本、参数名、约束条件都在演进。生成层的变化不应扩散到处理层与验证层。
4. **测试需要可回放。** 生成层不可复现（[PLAN §2.7](../PLAN.md)），但录制真实响应后回放是可复现的。

## 决策

**在 `providers/base.py` 定义统一的 Provider 抽象接口，所有生成调用只通过该接口。第一版提供三个实现。**

```text
providers/
├── base.py            抽象接口 + 统一错误类型
├── openai_image.py    真实实现（gpt-image-2 / gpt-image-1.5）
└── mock.py            离线实现，返回确定性的合成图
```

接口约定：

- 只暴露两个语义方法：`generate(prompt, size, ...)` 与 `edit(prompt, base_image, references, size, ...)`。
- **返回值必须包含 request ID 与原始请求摘要**，以支撑失败溯源。
- **所有 Provider 异常必须转换为项目内部错误类型**，上层不得直接捕获 SDK 异常。
- Provider 负责重试与退避；上层只看到"成功"或"终态失败"。

错误分类（决定重试策略）：

| 类别 | 处理 |
|---|---|
| 瞬态（429 / 5xx） | Provider 内部指数退避重试 |
| 参数错误 | 不重试，抛出可操作错误 |
| Moderation blocked | 不重试，抛出可操作错误 |
| 构图 / 帧数错误 | **不在此层处理** —— 交给 Repair Planner |

最后一条是关键边界：**Provider 只负责"调用是否成功"，不负责"产出是否合格"。**
产出质量由验证引擎判定，这两件事必须严格分离。

## 理由

Provider 抽象把三类不确定性（网络、模型输出、配额限制）全部关在一个模块内。抽象边界之外的所有代码
—— 处理、验证、修复决策、导出 —— 都是确定性的、可测试的、可离线运行的。

Mock Provider 不是"测试用的桩"，而是**一等公民**：Sprint 1 的退出门槛就是"不调用真实 API 即可走完整工作流"。
这保证了整个流水线的骨架在花第一分钱之前就已经验证过。

只暴露 `generate` / `edit` 两个方法，是为了防止上层代码依赖某个 Provider 的特有能力。
例如 `gpt-image-2` 强制高保真处理参考图、没有 `input_fidelity` 旋钮 —— 这个事实不应该泄漏到 pipeline 层。

## 后果

**正面**

- 开发期迭代完全离线，不触网、不消耗配额。
- 切换到 `gpt-image-1.5` 做透明背景降级只需换 Provider 配置。
- 单元测试与 golden 测试不依赖网络。
- 未来接入其他图像模型的改动被限制在一个文件内。

**负面**

- 抽象接口必须迁就"最小公分母"，无法直接利用某个 Provider 的独有特性。接受这个代价 —— 本项目对生成层的要求本就很朴素（给 prompt、给参考图、给尺寸、拿图）。
- Mock Provider 需要持续维护，使其产出的合成图足以驱动下游处理逻辑（例如必须真的画出 N 个格子、必须有键控色背景），否则 Mock 测试会流于形式。

## 备选方案

**A. 直接调用 OpenAI SDK，不做抽象**
被否决。会导致处理层与验证层的测试全部依赖网络，且透明背景降级路径无处安放。

**B. 引入通用多模型网关（如 LiteLLM）**
被否决。增加一层外部依赖，而本项目只需要两个模型、两个方法 —— 自己写这层抽象远比引入一个通用网关简单。

**C. 抽象层同时负责产出质量判定**
被否决。"调用成功"与"产出合格"是两个正交的问题。混在一起会让 Provider 层需要理解网格布局、帧数、身份一致性等业务概念，破坏分层。
