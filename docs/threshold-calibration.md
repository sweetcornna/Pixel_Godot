## 样本

6 个角色 × 5 个动作 = **30 个动作**，36 次 API 调用。

角色是**刻意挑轮廓差异极大的** —— 阈值要覆盖的正是这种差异：

| 角色 | 轮廓特征 |
|---|---|
| 骑士 | 人形持剑，基准形态 |
| 弓手 | 极瘦，带长弓 |
| 法师 | 宽袍遮住双脚 |
| 石魔 | 方肩远宽于胯，短腿 |
| 小恶魔 | 展开的蝙蝠翼远宽于身体 |
| 史莱姆 | **无四肢**，圆形软体 |

全部 30 个动作人工过图审核，**无一不合格**（审核图见生成目录的 `calib/review*.png`）。

## 调整策略是**不对称**的

放宽与收紧的风险不对等：**误报会让开发者关掉验证器**（PLAN §9.1 拒绝统一
阈值时给的就是这个理由），漏报只是少抓一个缺陷。6 个样本足以证明"某个阈值
太紧"，但不足以证明"某个阈值可以收多紧"。

### 有证据就放宽

**史莱姆的待机是本次最有价值的发现。** 它的产出完全正确 —— 挤压回弹
68 → 73 → 76 → 68，正是史莱姆该有的待机。可它的高度变化实测 **0.112**，
而 `idle` 的阈值是 **0.06** —— 会被判失败。

**人形调出来的阈值对非人形误报。** 这不是模型的问题，是阈值的问题。

`hurt` 的高度变化实测 0.248、阈值 0.25，只差 1%，同样放宽。

### 不轻易收紧

`walk` 的轮廓变化实测最大 0.078、阈值 0.20，看着可以收到 0.09 ——
但那是拿 6 个样本去赌第 7 个角色。留着。

### 锚点漂移例外

它是**绝对像素量，与角色形状无关**，30 个样本全部落在 0.18 ~ 0.66。
原来 `attack` 给 3px、`hurt` 给 2px，比实测宽 3~6 倍。统一收到 1px 仍有
1.5 倍余量。这一项的收紧有充分依据。

复验：30 个校准样本用新阈值全部通过（阈值若连自己的校准集都过不了就是废的）。

## 仍未校准

- `cast` / `travel` / `impact` / `loop` —— **没有样本**，维持初始值
- `death` —— 维持豁免。实测高度变化 0.818 ~ 1.419，比角色动作高一个量级，
  能定出的阈值只有 1.7 上下，那种数字拦不住任何真实缺陷
- **`up` 方向的 ×1.3 修正系数没有验证** —— 本次样本全是 `down`

## 顺带记录的生成层观察

- `slime · walk` **长出了小腿**，而请求里明写 "no limbs"。模型为了表现"走"
  自己加的。技术上帧是干净的（不影响几何校准），但这是身份漂移的一种。
- `golem · hurt` 第一帧左上角有几点杂散像素，孤立像素清理没能全部清掉。
