## 样本

6 个角色 × 5 个动作 = **30 个动作**，36 次 API 调用。

角色是**刻意挑轮廓差异极大的** —— 阈值要覆盖的正是这种差异：

| 角色 | 轮廓特征 |
|---|---|
| 骑士 | 人形持剑，基准形态 |
| 弓手 | 极瘦，带长弓 |
| 法师 | 宽袍遮住双脚 |
| 石魔 | 方肩远宽于胯，短腿 |
| 小恶魔 | 展开的蝙蝠翼远宽于身体 |
| 史莱姆 | **无四肢**，圆形软体 |

全部 30 个动作人工过图审核，**无一不合格**（审核图见生成目录的 `calib/review*.png`）。

## 调整策略是**不对称**的

放宽与收紧的风险不对等：**误报会让开发者关掉验证器**（PLAN §9.1 拒绝统一
阈值时给的就是这个理由），漏报只是少抓一个缺陷。6 个样本足以证明"某个阈值
太紧"，但不足以证明"某个阈值可以收多紧"。

### 有证据就放宽

**史莱姆的待机是本次最有价值的发现。** 它的产出完全正确 —— 挤压回弹
68 → 73 → 76 → 68，正是史莱姆该有的待机。可它的高度变化实测 **0.112**，
而 `idle` 的阈值是 **0.06** —— 会被判失败。

**人形调出来的阈值对非人形误报。** 这不是模型的问题，是阈值的问题。

`hurt` 的高度变化实测 0.248、阈值 0.25，只差 1%，同样放宽。

### 不轻易收紧

`walk` 的轮廓变化实测最大 0.078、阈值 0.20，看着可以收到 0.09 ——
但那是拿 6 个样本去赌第 7 个角色。留着。

### 锚点漂移例外

它是**绝对像素量，与角色形状无关**，30 个样本全部落在 0.18 ~ 0.66。
原来 `attack` 给 3px、`hurt` 给 2px，比实测宽 3~6 倍。统一收到 1px 仍有
1.5 倍余量。这一项的收紧有充分依据。

## 仍未校准（harness 已就绪）

- `cast` / `travel` / `impact` / `loop` —— **仍没有合格的真实样本**，维持初始值
- `death` —— 维持豁免。实测高度变化 0.818 ~ 1.419，比角色动作高一个量级，
  能定出的阈值只有 1.7 上下，那种数字拦不住任何真实缺陷
- **`up` 方向的 ×1.3 修正系数仍未用有效真实样本验证** —— 2026-07-30 的 30 个
  动作样本全是 `down`

2026-08-03 已固化[一键校准 harness](../tools/calibration/README.md)：固定 6 个角色的
`cast_down`、其中 3 个角色的 `walk_up`，以及火球/闪电链/治疗光环中适用的
`travel` / `impact` / `loop`，共 9 个资产单元、16 个动作样本、25 次固定调用。脚本
复用生产 pipeline 与 `validation/metrics.py`，关闭缓存并做调用对账，只写原始量测、
聚合、建议报告和审图路径，**绝不自动修改 `constants.py`**。

同日完整 mock 演练已 25/25 通过，量化证据入库在
`tools/calibration/reports/20260803T182416.480460Z/`（原图/GIF 大件按 live-gate

### 2026-08-05：live 运行已完成，阈值仍未改动

`gpt-image-2` 实跑 25/25，调用对账通过，量化证据入库在
`tools/calibration/reports/20260805T060618.921814Z/`。`constants.py` 的 SHA-256
运行前后一致（`run-manifest.json` 的 `constants.unchanged: true`）—— harness 没有
碰过任何阈值，**人工审图这道闸门尚未走**，所以下面只是候选证据，不是已完成的校准。

真实分布**有四组越过现阈值**：

| 动作 | 指标 | 实测 min～max | 现阈值 | 候选下限 |
|---|---|---:|---:|---:|
| `loop` | `silhouette_variation` | 0.7609～0.8850 | 0.3 | 0.89 |
| `loop` | `height_variation` | 0.4062～0.5714 | 0.2 | 0.58 |
| `travel` | `height_variation` | 0.2922～0.6889 | 0.4 | 0.69 |
| `cast` | `silhouette_variation` | 0.0434～0.5002 | 0.45 | 0.51 |

`walk` 与 `cast` 的 `height_variation` 全部远低于阈值（0.0000～0.1579）——按
不对称策略**不据此收紧**。

**`up` ×1.3 仍未被验证。** 三个 `walk_up` 样本实测 `height_variation`
0.0000～0.0435、`silhouette_variation` 0.0354～0.0859，连基准阈值 0.12 / 0.2 都
远够不着，更不用说 ×1.3 后的 0.156 / 0.26。系数既没被证实也没被证伪 ——
这批样本根本没让它派上用场，不能记成"已验证"。

### 这批证据的一处边界：`anchor_drift` 暂不可用于收紧

16 个动作样本里 **8 个（50%）的格线落在非整数位**（端点返回 `1774×887` / `2103×748`
/ `1717×916` / `1902×827` 这类不被 `cols` 整除的尺寸），其中包括**全部三个
`walk_up`**。切帧已按比例进行（Sprint 0 / A-1 的既定对策），但 `cell_box` 的
`round()` 仍会让格线偏离理想位置最多 0.5px，实测端到端主体位置误差最大 0.95px
（源图尺度），降采样到 64×64 逻辑像素后为 **0.137px**。

`silhouette_variation` / `height_variation` 的量级是 0.03～1.79，远高于这个噪声底，
**证据成立**。但 `anchor_drift` 这批实测只有 0.36～0.54px，0.137px 占到近 28% ——
所以本文"锚点漂移例外"那条允许的收紧，**在切帧格线取整修复落地并复跑之前不要执行**。

## 顺带记录的生成层观察

- `slime · walk` **长出了小腿**，而请求里明写 "no limbs"。模型为了表现"走"
  自己加的。技术上帧是干净的（不影响几何校准），但这是身份漂移的一种。
- `golem · hurt` 第一帧左上角有几点杂散像素，孤立像素清理没能全部清掉。
